### 1.= Цель и задачи

> «Гений — это один процент вдохновения и девяносто девять процентов пота.»
> — *Томас Эдисон*

**Цель проекта:** разработать и внедрить решение, соответствующее требованиям заказчика.

**Задачи:**
1. Собрать и проанализировать требования.
2. Спроектировать архитектуру решения.
3. Реализовать ключевые модули.
4. Провести тестирование.
5. Выполнить развёртывание и передачу заказчику.

### 1. Ожидаемый результат

- [ ] Работающий прототип
- [ ] Техническая документация
- [ ] Отчёт о тестировании

## 2. Этапы выполнения

### 2.1. Подготовительный этап

**Срок:** 1–2 недели
**Ответственные:** аналитик, менеджер проекта

1. Формирование команды.
2. Проведение интервью с заказчиком.
3. Составление технического задания (ТЗ).
4. Согласование сроков и бюджета.

### 2.2. Проектирование

**Срок:** 2–3 недели
**Инструменты:** ***Figma, Draw.io, Miro***

- Разработка UX/UI-макетов
- Проектирование базы данных
- Определение стека технологий
- Составление диаграмм (ER, UML, BPMN)

### 2.3. Разработка

**Срок:** 4–8 недель

1. Настройка репозитория и CI/CD.
2. Реализация backend-части.
3. Реализация frontend-части.
4. Интеграция внешних сервисов.
5. Code review и слияние веток.

### 2.4. Тестирование и внедрение

**Срок:** 1–2 недели

- Функциональное тестирование
- Нагрузочное тестирование
- Исправление критических багов ~~(а также не очень критических)~~
- Развёртывание на production
- Обучение пользователей

## 3. Роли и обязанности команды

| Роль | Обязанности | Загрузка |
|------|-------------|----------|
| **Менеджер проекта** | Планирование, коммуникация с заказчиком | 100 % |
| **Аналитик** | Сбор требований, ТЗ, документация | 50 % |
| **Разработчик** | Написание кода, code review | 100 % |
| **Тестировщик** | Тест-планы, регрессия, баг-репорты | 60 % |
| **Дизайнер** | UX/UI-макеты, дизайн-система | 40 % |
